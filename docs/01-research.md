# 项目调研与结论

## 1. 想解决的问题

用户希望有一个打开就能看电视的应用，减少在多个网站和播放器之间寻找频道的时间。核心体验是：看到频道列表、选择频道、立即播放；有收藏和搜索后，日常使用不需要重复配置。

## 2. GitHub 调研结果

| 项目 | 作用 | 对本项目的启发 | 参考 |
| --- | --- | --- | --- |
| `iptv-org/iptv` | 维护公开 IPTV 频道的 M3U 播放列表 | 可作为开发阶段的公开数据样本；按国家、语言、类别拆分，适合先加载小列表 | [GitHub](https://github.com/iptv-org/iptv) |
| `iptv-org/api` | 提供频道、流、Logo、节目单入口等 JSON API | 适合把频道名称、国家、分类、Logo 与播放 URL 分开管理 | [GitHub](https://github.com/iptv-org/api) |
| `4gray/iptvnator` | 跨平台 IPTV 播放器 | 验证了 M3U、XMLTV、收藏、搜索和外部播放器的产品组合 | [GitHub](https://github.com/4gray/iptvnator) |
| `aimen08/livebox` | Electron + React + mpv 播放器 | 说明浏览器视频标签之外，可以用 mpv/libmpv 提升格式兼容性 | [GitHub](https://github.com/aimen08/livebox) |

## 3. 可行性判断

技术上可行。M3U 是文本格式，频道条目通常由 `#EXTINF` 元数据和一个媒体 URL 组成；HLS（`.m3u8`）可以用浏览器原生能力或 HLS.js 播放。第一阶段不需要自建转码服务，也不需要把视频文件存到服务器。

产品上应先做“播放器 + 用户自有/公开授权列表”，再考虑频道目录服务。把不稳定或权利不明确的链接固化到应用中，会导致播放失败、下架和发布风险同时增加。

## 4. 结论

先做可运行的 Web 原型验证三件事：

1. M3U 读取和频道列表渲染是否足够稳定。
2. 浏览器对不同 HLS 源的播放和跨域限制是否可接受。
3. 用户是否需要“打开就有频道”，以及收藏、搜索、分组是否足够形成核心体验。

验证通过后，先做 PC 桌面端。PC 端更适合验证来源管理、播放错误、快捷键和长时间播放；之后再做 Android，并为 Android TV 单独补齐遥控器焦点导航和电视启动器适配。
