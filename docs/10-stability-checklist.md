# 设置与稳定性检查记录

## 本次补强

- 设置变更继续使用本地自动保存；设置面板保持紧凑，只保留播放、来源和稳定性相关选项。
- Electron 配置文件损坏、超限或版本无法读取时，会保留 `.corrupt-时间戳.json` 备份并使用默认配置启动，不再让主界面停在启动失败。
- 解析 Worker 初始化失败时，M3U 会回退到渲染进程中的受限同步解析路径，保证设置和播放界面仍然可操作；XMLTV 解析器保留给后续高级能力使用。
- 关闭窗口时清理播放器、解析服务和待保存计时器，尽可能保存最后一次配置。
- 本地播放列表选择失败、超过大小限制或取消后会清理旧文件状态，避免下一次添加来源误用旧文件。
- mpv/libmpv 尚未接入当前版本，因此不在设置面板中暴露不可用的播放器选项；后续接入时沿用现有 `PlaybackAdapter` 接口。
- 启动时优先恢复退出前正在播放的频道；默认来源和默认频道不再作为用户需要维护的设置。
- 播放列表来源直接放在设置面板内管理，避免从设置再打开第二个抽屉。
- 当前版本不展示最近观看、在线日志或节目单设置；EPG 数据模型和解析器保留但暂不进入 PC 用户流程。诊断信息由用户主动导出，导出内容只包含来源状态和脱敏事件记录。
- 播放控件移除原生 `title` 提示，统一使用延迟显示的 OSD tooltip，点击不会触发提示。
- 主画面的频道信息旁提供轻量频道列表入口，鼠标用户不必记住 `C` 快捷键；频道列表仍保持抽屉形式，不占用播放主区域。
- 播放列表删除采用二次确认；确认和取消会把焦点留在对应按钮，避免鼠标或键盘/遥控器误触。
- 切台后只更新左上角频道号、频道名和分组；不再显示独立的左下角频道提示，避免重复信息干扰观看。
- 直播缓冲时保留当前视频画面，只在画面中央显示轻量转圈提示；恢复播放后自动消失，只有重试耗尽才进入播放失败界面。
- 音量滑块同步输出百分比 `aria-valuetext`，静音按钮保留独立的静音/取消静音状态。
- 播放器最终失败时回写当前来源健康状态和脱敏错误类别；多频道来源显示“部分跳过”，单频道来源显示“失败”，播放恢复后清除旧错误。
- 主进程来源请求保留 HTTPS 重定向、HTTP 状态和超时语义，界面可以区分网络失败、超时、HTTP 错误和授权/地区限制，不记录完整 URL。
- 用户切台、删除来源或刷新同一来源时，旧的主进程请求会区分“主动取消”和“超时”，主动取消不会污染来源健康状态或弹出错误提示；播放成功后重置本次重试计数。
- Electron 使用单实例锁；重复启动只唤起已有窗口，不重复创建播放器和来源请求。
- 窗口状态保存宽度、高度和屏幕位置；如果保存的位置已不在任何显示器范围内，启动时只恢复尺寸并使用系统默认位置。
- Linux arm64 目录包可在当前 Mac 主机生成；AppImage 由 Linux CI 生成，`.deb` 在当前 Mac 上会在 fpm/gtar 阶段失败，正式发布需在 Linux CI 或 Linux 主机完成。
- 当前 Mac 已生成 Windows arm64 和 Linux arm64 目录包，并用 `file` 检查为对应 PE/ELF 可执行文件；Windows/Linux 真机安装、启动和硬件解码仍需在目标系统验收。
- Linux 包元数据已补齐维护者、主页和桌面关联字段；`open-tv.invalid` 与 `contributors@open-tv.invalid` 是当前工程占位值，正式发布前必须替换为真实项目主页和维护者邮箱。
- 设置模态浮层滚动条改为细窄、低对比度样式，并限制滚动回弹影响主播放区。
- macOS 窗口使用沉浸式标题栏，频道信息从顶部安全区开始布局；Windows/Linux 保持原生窗口框架。
- 自定义 `opentv://` 协议直接从应用资源读取并返回明确 MIME 类型，避免 `asar` 安装包在本地 `file://` 转发失败后出现空白窗口。
- macOS 隐藏标题栏提供独立顶部拖拽区域，并避开左侧交通灯按钮；桌面端窗口可以从播放画面顶部空白区移动。
- Electron 打包接入 Open TV 专属应用图标，使用电视屏幕、播放符号和底座的蓝色渐变标记，并生成 macOS `icon.icns`。

## 已验证流程

1. `npm run check`
2. `npm run check:contract`（v1 Schema、Kotlin 模型和 TV 按键语义）
3. `npm test`（11 项固定夹具测试）
4. `npm run pack:dir`（macOS arm64 目录包）
5. `npm run pack`（macOS arm64 目录包、ZIP 和 DMG 均成功；当前产物仍为未签名构建）
6. 启动应用后打开设置抽屉，确认来源管理、播放偏好、稳定性和诊断导出位于同一面板。
7. 修改设置并恢复原值，确认开关状态自动保存。
8. 关闭设置返回播放界面，播放失败后点击重试，确认窗口保持可操作并重新进入缓冲状态。
9. 退出并重新启动应用，确认优先恢复退出前的频道；导出诊断信息时不包含完整播放地址。
10. 等待当前频道重试耗尽后打开设置，确认来源卡片保留错误提示；重新成功播放后确认错误被清除。
11. 连续启动两次 Mac arm64 目录包，确认只保留一个 Open TV 进程和窗口。
12. 退出 Mac arm64 目录包后检查 `window.json`，确认保存了 `width/height/x/y`；重新启动仍能恢复可见位置。
13. 检查 `platforms/android` 的 Manifest、Compose/Media3 依赖、共享 Kotlin 模型和 TV 按键契约；本机使用临时 JDK 17、Android SDK 37 和 Gradle 9.6 运行 `:app:assembleDebug`，仓库 Android CI 同样保留该编译门禁。
14. 验证 Android `AndroidConfigCodec`/`AndroidConfigStore` 的 v1 字段映射、严格配置导入/导出、`M3uParser`/`XmltvParser`、`AndroidPlaylistLoader`/`AndroidEpgLoader` 的 HTTPS/HLS/元数据入口，以及 Media3 缓冲/播放/错误事件回传；目标系统仍需补充真实重启后的持久化、解析和播放验收。
15. 静态检查 Android TV 启动恢复、上一台/下一台、频道抽屉、设置抽屉、远程来源表单、本地 M3U/M3U8 文件选择、来源刷新/启停/删除和 D-pad 事件接线；目标设备仍需做焦点顺序与返回键验收。
16. 从最新 macOS arm64 目录包启动，确认 `opentv://app/index.html` 正常渲染、错误态播放按钮可见、控制条和设置入口可用；确认音量滑块点击后不出现浏览器默认白色焦点框。
17. Android debug 构建成功，产物为 `platforms/android/app/build/outputs/apk/debug/app-debug.apk`，包名 `org.opentv.android`、`compileSdkVersion 37`、`targetSdkVersion 37`；本机没有连接的 Android 设备，因此暂未进行 `adb install` 和遥控器/触屏验收。
18. Macmini 人工体验路径：启动后进入播放失败态，确认重试按钮、播放/暂停、上下换台、静音/音量百分比、全屏进入/退出、频道列表搜索入口和设置入口均可操作；在设置中验证来源删除二次确认、确认/取消焦点保持和关闭后返回播放界面。
19. 最新 Mac arm64 包启动后确认顶部拖拽区域可接收拖动，窗口仍保留左侧交通灯；应用包资源中存在 `Contents/Resources/icon.icns`。

Macmini 实机复核：退出前选择“CCTV第一剧场”（频道 02），窗口关闭后重新打开仍恢复到频道 02；音量滑块和百分比显示保持一致。
