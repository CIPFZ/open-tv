# Open TV 工程实施计划

这份文档把产品目标转换成可执行的工程顺序。当前仓库已经完成“电视优先”渲染层和 TypeScript 播放器闭环，并提供 Electron 桌面壳、后台解析线程与跨平台数据模型。后续工作应按阶段推进，不把尚未完成的能力误认为已交付。

## 当前交付边界

### 已实现

- 电视优先单屏布局：视频为绝对主体，控制层按操作显示，频道浏览使用临时抽屉。
- 首次启动自动加载并播放标明为研发样本的 HTTPS 频道源；正式发布前必须按授权和地区逐条审查或移除它。
- HTML5 Video + HLS.js 播放适配器，播放、加载、缓冲、错误、超时和有限次数退避重试状态。
- 上一台/下一台、键盘上下键、鼠标按钮和频道条换台；切台前销毁旧播放器。
- 应用内 0–100 音量、左右键/加减键、静音、播放/暂停、双击全屏、`F`/`Esc`。
- 左上角当前频道号/分组、短暂控制条和播放失败动作提示；切台不再弹出独立频道提示。
- 频道抽屉：名称/频道号搜索、分组筛选、当前频道高亮。
- 设置单抽屉：HTTPS URL、本地 M3U/M3U8、多个来源切换、刷新、启用/停用、删除、频道数和最后更新时间，与播放偏好及稳定性选项位于同一面板。
- 播放列表来源健康状态：加载中、可用、部分跳过、失败，以及网络、超时、权限/地区、HTTP、格式、空列表和不安全地址分类。
- 设置居中模态浮层：自动播放、音量记忆、自动全屏、网络超时、重试次数和诊断导出；节目单入口暂不放入 PC 设置。
- 本地状态保存：播放列表元数据、当前来源、上次频道、音量、静音和播放偏好；启动时按上次频道恢复。
- Electron 安全壳：单窗口、`contextIsolation`、sandbox、禁用 Node 暴露、导航/新窗口限制、受限 IPC。
- `src/shared/models.ts` 中的频道、来源、EPG 节目、播放偏好、播放错误和 `PlaybackAdapter` 接口。
- `platforms/android` 中已建立与 v1 配置契约对应的 Kotlin 数据类、JSON 编解码、本地配置存储、M3U 解析与 HTTPS 来源加载边界、启动频道恢复规则、Media3 播放边界和 Android TV 遥控器动作映射。

### 当前未实现

- EPG 的 XMLTV 下载、解析、时区归一化和当前/下一节目基础链路保留在共享层；当前 PC 版本暂不加载或展示节目单，等有稳定授权来源后再重新开放。
- 频道号排序、跨播放列表合并去重、来源健康指标的主动探测和批量管理。
- 播放重试计数的持久化、按需频道健康检查和失效源提示。
- Electron 的诊断导出扩展和安装包签名。
- mpv/libmpv 播放后端、系统音量控制和硬件解码增强。
- Windows/macOS/Linux 的 CI 打包入口已存在，并在各自 runner 先构建目录包再生成归档/安装器；自动更新、崩溃恢复、签名和目标系统安装验收仍待发布阶段完成。
- Android Media3 客户端、Android TV Compose 焦点界面和跨平台配置 JSON 读写（当前已有可导入的 Android app 模块、Media3 播放边界与缓冲/播放/错误事件回传、Activity 生命周期暂停/恢复、配置导入/导出、电视优先控制条、v1 播放列表/频道模型、XMLTV 解析、受 HTTPS/重定向/大小限制保护的 XMLTV 加载与当前/下一节目层、JSON 编解码、HTTPS 来源加载边界、频道侧栏、与桌面一致的居中设置弹层、远程来源编辑表单、系统文件选择器导入以及来源刷新/启停/删除；仓库 CI 和本机临时工具链都已通过 `:app:assembleDebug`，生命周期测试、真机焦点验收和完整安装仍待实现）。

## 开发顺序

### 阶段一：核心观看闭环（已完成，持续验证）

验收重点是“打开应用后可以看、可以上下换台、可以调音量、可以退出全屏”。先用小规模、公开且仅用于研发的 M3U 样本验证播放器；任意单个频道失败不能阻塞其他频道。

### 阶段二：PC 正式应用

1. 已将渲染层拆成 `src/renderer` 的 TypeScript 模块，preload API 负责桌面网络、配置和文件选择。
2. 已将配置接入 Electron `userData/settings.json`，保留版本号、边界校验和窗口大小保存骨架。
3. 已加入 XMLTV 解析线程和按 `tvg-id` 匹配能力；PC 用户界面暂不暴露 EPG，避免为普通观看流程增加配置负担。
4. 已加入错误码映射、重试退避、请求取消和诊断导出；日志只记录错误类别，不写入完整 URL。
5. 已建立 `electron-builder` 的 macOS、Windows、Linux 配置；当前 Mac 已验证 macOS arm64、Windows arm64 和 Linux arm64 目录包，图标、签名、安装器和目标系统真机验收仍待发布阶段完成。

### 阶段三：播放稳定性

1. 实现 `PlaybackAdapter` 的 mpv/libmpv 版本，保留相同的换台、音量和 OSD 状态机。
2. 对用户主动配置的来源做按需健康检查，不批量扫描第三方站点；记录网络超时、HTTP、解码和地区限制状态。
3. 增加有限次数重试和“重试/上一台/下一台”动作；播放器崩溃时只重建播放器，不退出窗口。
4. 在原生端评估系统音量、硬件解码和低延迟 HLS，逐平台记录差异。

### 阶段四：Android

- 使用 Kotlin + Media3/ExoPlayer 实现触屏播放器，复用本目录中的 JSON 模型和 M3U/XMLTV 解析规则。
- 支持前后台恢复、网络变化重试、配置导入导出和系统返回行为。
- 通过版本化配置格式迁移 PC 端的来源、频道、上次频道和偏好；不上传观看历史。

### 阶段五：Android TV / Google TV

- 使用 Media3 播放，所有可操作控件提供明确的焦点顺序和大尺寸状态反馈。
- 遥控器上/下换台、左/右调音量、确认打开频道列表、返回关闭抽屉或退出全屏。
- 增加 TV 启动器入口、横向大屏频道列表、无触控操作验收和电视安装包。

## 数据与安全约束

- 播放列表只当作数据读取，不当作 HTML 页面执行；PC 端远程 URL 仅允许 HTTPS，拒绝脚本协议和带凭据 URL。
- 不绕过登录、DRM、付费验证或地区限制，不通过 Open TV 服务器代理、缓存或转码视频。
- 生产版本不内置来源不明的频道；研发示例源必须保留来源说明和移除入口。
- URL、账号、Token 和完整播放列表内容不得写入日志；配置导出由用户主动触发。
- 大型列表解析需要分批或放到 worker，播放器切台时取消旧请求并销毁旧实例。

## 当前里程碑与后续检查

当前里程碑是“可安装的电视优先 PC MVP + Electron 安全壳 + 固定夹具回归测试”。EPG 解析能力暂作为共享层预留，不进入当前 PC 观看流程。下一次迭代应优先完成三平台安装验收、按需来源健康检查、Android CI 编译后的 Media3 播放事件和配置迁移，再扩大播放器兼容范围。每个阶段都需要用真实的公开或授权源进行播放、失败、切台、重启和数据迁移验收；固定夹具保证核心解析和配置恢复不依赖第三方网络。
