# PC 版开发前的技术与功能决策清单

界面方向已经确定为“电视机优先”。下面这些问题会直接影响代码结构，建议在进入正式 Electron 开发前定下来。

## 1. 播放后端怎么分阶段

### 推荐方案：先浏览器 HLS，后原生播放器

- P1：使用 HTML5 `<video>` + HLS.js，先完成 M3U8 播放、换台、音量和全屏。
- P2：遇到浏览器无法处理的格式、重定向或硬件解码问题，再接入 mpv/libmpv。
- 播放器通过统一的 `PlaybackService` 接口切换，界面不直接依赖具体播放器。

这样可以先快速验证产品，不会一开始就引入原生播放进程、打包和跨平台依赖。

## 2. 上下换台的规则

### 推荐方案

- 上下键只在当前有效频道列表中移动。
- 默认按播放列表原始顺序排列，后续再支持频道号排序。
- 当前频道播放失败时，不自动连续跳过很多频道，只显示“重试 / 上一台 / 下一台”。
- 切台时先停止旧流，再建立新流；连续按键时取消未完成的旧请求。
- 每次切台更新左上角频道号、频道名和分组，不额外弹出频道提示层。

需要确认的产品偏好：频道顺序是“播放列表顺序”还是“频道号顺序”。首版建议使用播放列表顺序，最稳定也最容易解释。

## 3. 音量是应用音量还是系统音量

### 当前决定：先做应用音量验证，保留完整界面

这里的“应用音量”是播放器自己的音量：拖动效果图中的音量条只改变当前视频的播放音量，并不改变 macOS、Windows 或 Linux 的系统主音量。实现上对应视频播放器的音量和静音状态。

第一阶段先验证音量条、静音、快捷键和播放状态联动；主界面仍按照效果图完整呈现。系统音量控制作为后续 Electron 原生能力增强，不影响当前的界面设计。

## 4. 默认频道源怎么处理

### 推荐方案：示例源 + 用户来源

- 内置一个仅用于演示的公开示例源。
- 用户可以添加自己的 M3U/M3U8 URL 或本地文件。
- 正式发布前逐条审查内置源的授权和地区限制。
- 不把“自动抓取所有免费频道”作为产品功能。

## 5. 节目单是否进入第一版

### 推荐方案：可选增强

主播放和换台不依赖 EPG。只有来源提供有效 XMLTV 时，才在 OSD 或频道抽屉里显示当前节目和下一节目；没有节目单就隐藏该区域，不显示空状态面板。

## 6. 播放列表管理放在哪里

### 推荐方案：独立管理抽屉

主界面只保留一个低存在感的“Playlist”入口。管理抽屉负责添加 URL、导入文件、刷新、删除、启用/停用来源，并显示上次加载时间和频道数量。

## 7. 本地数据怎么保存

### 推荐方案：分阶段迁移

- Web 原型：`localStorage`。
- Electron MVP：`electron-store` 或本地 JSON 配置，保存来源、最近频道、窗口和快捷键偏好。
- 需要多列表、健康状态和 EPG 缓存后，再迁移 SQLite。

播放列表 URL 可能包含账号信息，日志中不得打印完整 URL；界面也要允许用户删除本地来源。

## 8. 键盘和遥控器映射

### PC 首版建议

| 操作 | 快捷键 |
| --- | --- |
| 上一台 / 下一台 | `↑` / `↓` |
| 音量减 / 加 | `←` / `→` 或 `-` / `+` |
| 静音 | `M` |
| 播放 / 暂停 | `Space` |
| 全屏 | `F` |
| 退出全屏 / 关闭抽屉 | `Esc` |
| 显示频道条 | `C` 或上下键 |

Android TV 后续沿用“上下换台、左右调音量”的心智模型，再补焦点导航。

## 9. 错误处理要做到什么程度

首版至少区分：播放列表加载失败、频道 URL 失效、网络超时、跨域/请求限制、地区不可用和播放器解码失败。用户看到的是简短动作提示：重试、上一台、下一台、打开播放列表；详细错误只放在诊断面板。

## 10. PC 打包和平台范围

### 推荐顺序

1. macOS 开发和验证。
2. Windows 打包与快捷键验证。
3. Linux 作为兼容性构建，不在首个迭代追求全部发行版适配。

Electron 主进程负责窗口、配置和播放进程；渲染进程只负责界面和用户操作。这样将来替换 HLS.js 或加入 mpv 时，界面无需重写。

## 建议现在确认的 4 个答案

1. 首版频道顺序是否采用播放列表原始顺序？建议：是。
2. 首版是否只做应用音量？建议：是。
3. 首版是否把 EPG 作为“有数据才显示”的可选功能？建议：是。
4. 首个正式打包是否先支持 macOS + Windows？建议：是，Linux 随后跟进。

## 分阶段实现原则

界面完整度和功能完成度分开管理：

- **第一阶段**：完整主界面骨架、播放、上下换台、应用音量、静音、全屏和错误状态。
- **第二阶段**：真实播放列表管理、频道搜索、节目单和来源刷新。
- **第三阶段**：系统音量、mpv/libmpv、健康检查和跨平台打包增强。

未完成的辅助功能可以显示为入口或空状态，但不能挤占播放画面，也不能改变主界面的电视机形态。
