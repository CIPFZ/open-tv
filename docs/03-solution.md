# 产品与实现方案

## 1. MVP 范围

### 一级功能（界面和交互必须完整）

- 播放画面、自动播放和播放错误提示
- 上一台 / 下一台、音量、静音、全屏
- HLS 播放、暂停、音量、全屏
- 当前频道名称、频道号、加载失败和重试提示
- 键盘快捷键和操作时的 OSD 控制层

第一阶段先实现播放、上下换台、应用音量、静音、全屏和错误状态；其他入口仍按照效果图保留，通过阶段迭代逐步接入真实数据。

### 二级功能（辅助观看）

- 远程 M3U URL 和本地 M3U 文件导入
- 频道分组、搜索、快速频道条
- 播放列表切换和手动刷新
- 来源状态和失败提示

### 三级功能（管理设置）

- 多播放列表合并、去重和排序
- 频道健康检查与失效提示
- 退出前频道恢复和播放偏好
- 网络超时和重试设置
- Android TV / Google TV 安装包
- 桌面端 mpv/libmpv 播放后端（后续扩展）

### 暂不做

- 收藏主导航、推荐内容和海报墙
- 账号体系、订阅收费和云端同步
- 自建视频转码、缓存或代理
- 自动搜集来路不明的“免费频道”
- 录制、回放、时移和内容下载

## 2. 技术选型

| 层 | 选择 | 原因 |
| --- | --- | --- |
| 第一阶段界面 | Vite + TypeScript + 原生 HTML/CSS | 保留轻量界面，同时支持解析 worker、类型检查和可重复构建 |
| HLS | 原生 `<video>` + HLS.js | Safari 等浏览器可走原生，其余浏览器使用 HLS.js |
| 本地设置 | Electron `userData/settings.json`，Web 回退到 `localStorage` | 不需要账号和数据库即可保存最近频道、来源和偏好 |
| PC 桌面端（首个正式版本） | Electron + TypeScript，保持 HTML/CSS 界面，播放后端预留 mpv/libmpv | 复用当前 Web 原型，减少框架层，优先解决 Windows/macOS/Linux 的安装、窗口和播放稳定性 |
| Android TV 候选 | Kotlin + Jetpack Compose + Media3/ExoPlayer | 遥控器焦点、电视启动器和系统媒体能力更自然 |
| 节目单 | XMLTV 解析器 | 与 IPTV 生态兼容，避免自创格式 |

选择“Web 原型 → PC 桌面端 → Android → Android TV”的顺序，是为了先验证数据和播放可行性，再逐步补齐平台能力。PC 首版暂定 Electron：它可以直接复用 HTML、CSS、JavaScript 原型，并为后续的本地播放进程、窗口控制和安装包提供清晰边界。若稳定版本对安装包体积和内存占用有更高要求，再评估 Tauri；不在 P1 阶段同时维护两套桌面壳。

## 3. 关键用户流程

1. 首次打开：加载内置的研发示例源并自动播放上次退出时的频道，找不到时回退到首个频道。
2. 用户用上下键换台，用左右键或音量键调节声音。
3. 操作时显示短暂 OSD；无操作时画面回到沉浸式观看状态。
4. 用户打开频道条，搜索并跳转到指定频道。
5. 在右侧 Settings 覆盖层的播放列表来源区域粘贴 M3U URL 或导入本地文件；PC 和 Android TV 保持同一信息结构。

## 4. 验收标准

- 10 秒内完成一个可用 M3U 的解析并展示首屏频道（以网络状况允许为前提）。
- 频道搜索对名称和分组生效，上次频道和播放列表刷新页面后仍保留。
- 至少能播放一条可公开访问、无需鉴权的 HLS 源；源失效时不会卡死整个界面。
- 用户可以删除或替换来源，应用不上传播放列表内容。
- 窄屏和桌面窗口均可使用，播放区不会遮挡频道操作。
